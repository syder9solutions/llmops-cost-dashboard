# Project 12 — LLMOps Cost & Latency Dashboard

A self-contained LLMOps observability control plane: a ** LiteLLM-style LLM
gateway** that traces every call end-to-end, attributes **cost per request /
feature / user**, tracks **latency percentiles (p50/p95)** and TTFT, serves
**exact + semantic caching**, runs **alerting** on cost/latency/error
regressions, and renders a **zero-dependency HTML dashboard** — then uses all
of it to move a real number: **the semantic cache cut cost/1k requests 84.4%
and p95 latency 60.3%** on a live workload (the cross-stage `$/1k` delta mixes
model tiers — see the comparability caveat below; cache hit-rate and p95 are
the primary evidence). These figures come from `evals/report.json` and are
checked against the README by `tests/test_readme_consistency.py`.

## Architecture

```
app/            FastAPI service: POST /v1/chat/completions, /v1/embeddings,
                GET /stats, /spans, /alerts, /traces/{id}, /dashboard
src/
  tracing.py    span tree (trace_id/span_id/parent), stage timing, TTFT
  store.py      append-only SQLite trace store (WAL, indexed)
  pricing.py    per-model price table, $ = in·p_in + out·p_out (+ embed)
  cost.py       attribution rollups: request→feature→user, per-model
  cache.py      exact cache (content hash) + semantic cache (SimHash LSH)
  semanticsim.py 64-bit SimHash + hamming-band LSH, cosine-equivalent
  metrics.py    latency percentiles (nearest-rank p50/p95/p99), hit-rate
  alerts.py     rules: cost-spike, p95-drift, error-rate, drift (PSI)
  applogic.py   /v1/chat/completions pipeline: trace→cache→call→cost→alert
  server.py     uvicorn bootstrap (127.0.0.1)
  config.py     env + .env loader (no external deps)
  omniroute.py  httpx OpenAI-compatible client, retries, error classes
scripts/
  run_baseline.py         phase 0: trace-only workload (~600 live calls)
  run_cache_ab.py         phase 1: A/B exact vs semantic (~600 live calls)
  run_ablation.py         phase 2: 3×4 routing/model ablation (~84 live calls)
  run_alert_eval.py       alert precision: 6 scenarios ×20 trials (synthetic)
  gen_workload.py         deterministic query workload generator (seed 20261212)
  run_demo.py             serve dashboard (like boot_check, non-daemonizing)
  verify_cost_accuracy.py token accounting audit: $ == Σtokens×price
  make_report.py          aggregates evals/*.json → evals/report.json + md table
  reset_traces.py         wipe trace store between experiment phases
tests/          offline unit+integration tests (no network; PYTHONPATH unset)
evals/          results/ (phase summaries), report.json (headline numbers)
data/           traces.db lives here (gitignored)
```

## Reliability: retries + admission control

The gateway client (`src/omniroute.py`) survives the real failure modes of a
shared LLM gateway:

- **Failure classification**: transport errors, HTTP 5xx/408/409/429 are
  transient (bounded, jittered exponential backoff); other 4xx are permanent
  and raised immediately. Provider/system errors stay `RuntimeError` subclasses
  and never masquerade as client validation errors.
- **Quota walls are not hammered**: a 429 whose `retry_after` exceeds
  `MAX_RETRY_WAIT_S` is raised on first sight (a 5-hour quota reset cannot be
  waited out inside a request budget).
- **Admission control**: `MIN_CALL_INTERVAL_S` (default 0.75s) is a
  process-wide minimum spacing between outgoing calls, so a concurrent
  workload cannot trip the provider's per-org rate limit with its own burst.
  Verified: 30/30 live calls at 2 workers, zero 429s (vs 12/53 failing before).

These are covered by offline tests in `tests/test_retry_policy.py`.

## Cost model

Per-call cost is computed from the gateway-reported token usage × a per-model
price table (`src/pricing.py`), in the OpenAI-compatible tradition
(LiteLLM/Langfuse-style attribution). Prices are declared per 1M tokens in a
versioned, source-controlled table; every $ number on the dashboard traces to
`(prompt_tokens, completion_tokens) × price`. `scripts/verify_cost_accuracy.py`
recomputes Σ(tokens×price) from raw spans and asserts it equals the stored
attribution to the cent (0 tolerance) — that is our "matches the provider
bill" guarantee for a gateway that does not expose provider billing.

## Instrumentation overhead

Tracing is pure-Python span bookkeeping + one SQLite insert per span; the
gateway measures its own overhead (`overhead_ms` span attribute) and the
dashboard reports it (target < 5 ms median). See `evals/report.json`.

## Alerting

Six rules over the store: cost-per-1k spike, p95 latency drift, error-rate
jump, output-token distribution drift (PSI), semantic-cache hit-rate collapse,
budget burn (per-user/day). Each rule returns a firing decision + human
reason. `scripts/run_alert_eval.py` replays label-controlled synthetic
scenarios (regression vs steady traffic, 20 trials each) and reports fire rate
+ false-alarm rate per rule.
